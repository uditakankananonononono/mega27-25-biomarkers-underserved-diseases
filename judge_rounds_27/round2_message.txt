 CodonContext: a fail-closed CDS constraint tool with no
 expression claim
 Candidate-specific working report, September 25, 2026. This project is separate from the aggregate item-27 manuscript. A
 later same-protein, one-host mRFP expression analysis now supplies real paired construct measurements, but does not test
 the original cross-host CAI-gain/yield question or establish a new design method. The useful software deliverable is a
 tested CDS-constraint and provenance checker that refuses to turn codon metrics into yield predictions.

 Abstract
 Codon adaptation index (CAI) is a descriptive measure of how supplied synonymous codon weights match a particular
 usage table. Raising a CAI value does not, by arithmetic alone, prove that a protein is expressed, secreted or functional.
 The original candidate proposed testing whether CAI gain predicts experimentally measured expression across hosts under
 held-out GC and secretion constraints. The original examples lacked paired construct measurements, and a later mRFP
 cohort supplies only one protein in one host; four source-header holdouts show unstable calibration (macro R2 -0.305). We
 therefore keep the fallback: a standard-code coding-sequence checker for protein identity, whole and sliding-window GC,
 forbidden DNA motifs, homopolymer runs and supplied host-specific relative codon weights. It refuses invalid inputs and
 always leaves expression_prediction null. Three exact UniProtKB/NCBI RefSeq protein-CDS pairs were retrieved
 and crosschecked; their CDS translations match the corresponding protein sequences. These real sequences test parsing and
 translation, not expression. The software gate passes; the proposed host-/protein-held-out CAI-gain biological question
 remains unassessable. The mRFP early-codon result reproduces a published theme and is not a new discovery.

 1. Initial biological question and pivot
 A codon optimization study would need multiple constructs encoding the same protein, measured protein yield in multiple
 expression hosts, and a defined separation of train and test by host, GC stratum, secretion pathway or laboratory. It would
 compare a CAI-only expectation to the observed yield after controlling for composition and context. A collection of
 coding-sequence accessions alone does not supply such a label. Codon choice also affects mRNA structure, ribosome
 dynamics, motif creation, regulatory elements and host stress, none of which is captured by a single CAI value.
 Because that data gate was not met, the computational task is narrower. A user can submit a candidate and optional
 reference DNA CDS. The tool checks whether it encodes the same polypeptide and satisfies explicit, user-supplied
 sequence constraints. A lack of protein identity is a hard error. Constraint violations are returned as positions and values,
 not turned into a predicted expression rank. A user may supply relative codon adaptiveness weights for descriptive CAI
 arithmetic, but the tool will not invent a host table or measured response.

 2. Algorithm and formulas
 For a CDS of length L nucleotides, valid input requires L>0, L divisible by 3, only A/C/G/T, initial ATG, a terminal stop
 codon TAA/TGA/TAG and no internal in-frame stop. Translation uses the standard nuclear/bacterial codon map. A
 candidate and reference must have identical translated amino-acid strings; the stop is omitted from the protein sequence
 hash. This is a sequence-preservation check, not a statement that the protein folds or behaves identically in different hosts.
 Whole-sequence GC fraction is (count(G)+count(C))/L. The optional sliding window of W nucleotides visits every
 position from 0 through L-W, inclusive, and compares each window's GC fraction to supplied minimum and maximum. A
 forbidden motif is matched against exact uppercase DNA text and its first zero-based position is reported. Homopolymer
 check flags a run longer than the supplied maximum. Limits must be finite and in [0,1] for GC, W must be an integer from
 3 through L, and contradictory min/max ranges are rejected. Boolean and NaN values are refused; silently interpreting
 them as numbers could make a wrong construct appear feasible.
 For each non-Met, nonsingleton synonymous codon c, the optional CAI is the exponential of the arithmetic mean of log
 relative-adaptiveness weight w(c), where each required weight is in (0,1]. The tool returns null when there are no variable
 synonymous codons. CAI gain is candidate CAI minus reference CAI only when both sequences and all necessary weights
 are supplied. This is an arithmetic difference, not a percentage expression gain. Supplying weights without their host and
 experimental origin can make a number look precise while remaining biologically uninterpretable.

 3. Real accession provenance
 accession_audit.py fetched exact UniProtKB records and the linked NCBI RefSeq nucleotide records. For each
 protein, it selected the GenBank CDS feature with the matching protein ID, extracted the DNA at annotated coordinates,
 translated it and required exact equality to the separately retrieved UniProtKB protein sequence. This includes reverse-
 complement feature handling where necessary. The results and SHA-256 response digests are in accessions.json.

 4. Tool behavior and examples
 The committed example.json contains synthetic short synonymous CDS inputs, a small illustrative adaptiveness table
 and constraint values. Run python3 projects/codon_context/codon_context.py projects/codon_context/
 example.json from repo root. A normal result names constraints_pass or constraints_fail, records violation
 positions, hashes the translated protein and returns expression_prediction: null with an explicit warning. A
 candidate that changes the amino-acid sequence raises an error rather than returning a comparable CAI gain. Missing
 codon weights, zero or negative weights, nonfinite values, impossible window sizes, contradictory GC bounds and
 ambiguous nucleotides fail closed.
 The tests cover valid synonymous comparison, altered protein rejection, invalid start/stop/ambiguity, forbidden motifs, GC
 windows, malformed numerical constraints and all three real accession CDS checks. They test software behavior, not
 whether any gene expresses in a lab. No code enumerates or searches synonymous designs. This is an auditor of proposed
 CDS sequences, not a codon optimizer that can find a satisfying sequence on its own.

 5. Evidentiary gate and missing cohort
 The software gate is concrete: preserve translation, enforce explicit constraints, and never claim yield from unmeasured
 codon arithmetic. That gate passes the supplied tests. The original biological hypothesis remains unassessable: the later
 mRFP cohort provides sequence and expression for one protein/host but not the multi-host, protein-held-out, GC- and
 secretion-controlled design needed to test CAI-gain generalization. A stronger cohort would include original construct
 sequences, host strain, growth conditions, measured expression or yield, assay variability and secretion status or
 compatible constraints for each construct. A host-held-out and a secretion-held-out comparison would be needed to test
 whether CAI gain adds predictive value beyond GC and simple sequence features. A single best-performing recombinant
 protein or an accession-only CDS database would not suffice.
 Even with a paired cohort, a robust test would freeze the unit of independence: constructs from the same protein or
 publication may share protocol and label noise. The final model should be assessed on a genuinely new host/lab or held-out
 protein family, with confidence intervals and a baseline that uses composition alone. That is future work, not a benchmark
 result concealed in this report. No external wet-lab measurements were acquired or inferred from UniProt/RefSeq
 identifiers.

 6. Safety and misuse boundaries
 A scientifically honest CDS checker should be predictable when input is malformed. It rejects non-ACGT bases, internal
 stops and candidate/reference protein mismatch before reporting a passing constraint status. It does not silently accept
 Boolean numeric fields or cast fractional window lengths to integers. DNA motif and GC restrictions can matter for
 cloning or synthesis, but the user remains responsible for choosing biologically appropriate constraints, host weights and
 gene identity. A passing output means only that the supplied sequence meets the supplied arithmetic rules; it is not a safety,
 expression, manufacturing or clinical clearance.
 The tool currently assumes the standard genetic code and an ATG start. Mitochondrial genomes, organisms with alternate
 codon tables, noncanonical starts and engineered code systems require a separate specified mode. Secretion is not modeled,
 nor are mRNA secondary structure, RNA stability, rare-codon stalls, immunogenicity or regulatory sequence effects. No
 wet-lab phenotype can be reconstructed from the source accession metadata.
