# MEGA27-25: ten separate disease projects, shared core only

The repository's `src/`, `scripts/`, `results/` and `paper/` currently form a cross-disease research core. They are not ten completed disease papers. Each disease directory below is a separate project with its own accession-unit inventory, genuinely used external-service ledger, methods/results, reproducibility checks, substantive 50-page manuscript, and published-comparator or validated-discovery gate. A shared code library can be reused, but its use does not automatically count an external service or accession for a disease. A cohort's nested GSMs remain nested within their GSE and, where applicable, repeated people.

`per_disease_gate_audit.csv` is the first conservative snapshot. It tags manifest rows by disease role, so 26 untagged GPL platforms, the HGNC mapping set and the STRING graph are not assigned to a disease without source-to-use proof. It is neither an exhaustive per-disease source inventory nor proof of independent studies. The program-wide 40 services, 1,494 accessions and 49-page PDF cannot satisfy each of ten separate gates. Long COVID entered the study through later P36-P38 follow-ups; it lacks an original meta-discovery disease split and must develop an independent disease-level protocol rather than inherit one from the nine original labels.

Each `README.md` is a scaffold, not a paper. The 1 PM deadline for ten full projects cannot be represented as met without independent ledgers and results for each.

## Novelty and independent-critique gate

The owner has rejected incremental benchmark-only papers. Every disease directory now has a distinct `NOVELTY_PLAN.md` naming an unproven, falsifiable contribution and its refuting test. These are plans, not discoveries. No disease project currently has defensible new biological discovery, a validated novel method, or a measured published same-task advantage. After an individual project actually meets its independent source, service, page and scientific gates, preserve every verbatim ChatGPT ISEF-judge prompt/critique/fix iteration in that project; do not run a premature loop on a scaffold or pass off model opinion as external validation.
