# GSM overlap audit, extractable resource - version 0.1

Run `python3 scripts/source_overlap_audit.py --split results/split_locked.csv --labels-dir results/series --output results/source_overlap_audit.json` from the repository root. Input split CSV needs `disease,tag,gse,split` fields, one row per disease/tag; for each row supply `<disease>__<tag>.labels.csv` in `--labels-dir` with a `gsm` column of source GSM identifiers. Output JSON records every literal same-disease inter-series GSM-overlap edge with the exact shared IDs, the deterministic dropped subset (fewer labeled GSMs; tie drops higher numeric GSE), and the retained series. It fails on absent/empty files, duplicate GSMs within a series, ambiguous tie accessions, invalid GSMs or duplicate split rows. Four tests include a synthetic discovered/validation overlap, duplicate, missing-file and locked-project replay.

On the pinned shared split (60 series rows), the standalone runner detects **six overlap edges**, drops **six series** and retains **54**; the dropped tags reproduce the pre-existing locked correction exactly. The largest shared edge has 442 GSMs, between GSE149437 and GSE149440. These are repeated identifiers, not new biological observations. The tool is an extractable source-audit component with explicit input and output contracts, not a novel algorithm or a demonstrated win over a published curation tool. It does not detect reuse under different GSM IDs, recover patient identity, clinically adjudicate label conflicts, or prove the 54 retained series are independent cohorts. Before claiming a method benchmark or production resource, add a source-labeled evaluation corpus and compare false positives/negatives, coverage and runtime against a named existing audit workflow.
